# 开源远程控制方案调研（BilldDesk / CrossDesk vs UU 远程）

> 调研日期：2026-11-24
> 说明：以下结论均基于项目 README、GitHub 公开数据与近期 issue 整理，**尚未进行实机安装与端到端延迟测试**；性能数据多为作者自述，实际体验需以实测为准。

## 一、BilldDesk（`galaxy-s10/billd-desk`）

个人开发者基于 WebRTC 实现的 ToDesk 类远程桌面工具（调研时约 9.3k Star）。

### 1. 与 UU 远程、ToDesk 的区别
- 主打免费与可自建服务：作者对标 ToDesk，连接时长和次数无限制；Pro 版支持安卓被控、隐私屏、虚拟屏、自定义设备码，网页端也可直接发起控制（这些能力在 ToDesk 中大多需要付费）。
- 提供 ToDesk 缺少的附加功能：远程录屏、批量群控、一台控多台。
- UU 远程偏游戏与低延迟场景，属于成熟商业产品，有官方节点与售后支持，开箱即用、无需折腾。

### 2. 效果（作者自述）
- 作者宣称实测可达 2K/60fps、2K/120fps（RTX 5070 被控环境）。
- 支持 H264 / H265 / AV1 硬件编码以及驱动级键鼠。
- 缺少第三方评测；实际延迟与画质高度依赖网络环境和免费官方中继带宽，稳定性无法保证。

### 3. 类似产品
- **RustDesk**：最成熟的开源远程桌面方案，支持自建，社区规模与生态远大于 BilldDesk；追求稳定时更省心。
- **Sunshine + Moonlight**：游戏串流方案，延迟最低。
- **Parsec**：游戏向商业远程控制产品。
- **商业综合方案**：向日葵、AnyDesk、TeamViewer、ToDesk、UU 远程。

### 4. 好用程度与风险评估
- **优点**：功能全面、基础免费、跨平台、支持浏览器直接控制。
- **风险**：
  1. Pro 版不开源，源码需付费订阅购买。
  2. 开源版 README 明确标注“未发布稳定版，不建议用于生产”，且提到存在两个几乎无法修复的已知问题，作者因此重写了 Pro 版。
  3. 个人项目，长期维护与安全审计弱于 RustDesk。
- **结论**：适合临时远程、折腾体验或节省会员费；**不建议**将重要设备的长期无人值守只托付给它。部分宣传视频称“完全超越”属于营销话术，需谨慎看待。

### 5. 公网 IP 与部署要求
- **普通使用**：不需要公网 IP，也不需要自建，直接下载客户端（`desk.hsslive.cn` / GitHub Releases `v0.76.0`）连接官方服务器即可，依赖 WebRTC 打洞，打不通时走中继。
- **自建部署**：如需隐私与稳定性，需一台带公网 IP 的服务器部署信令与中继（Node + MySQL + Redis + Coturn），被控电脑本身仍无需公网 IP。开源版 Docker 一键部署在调研时尚未完成，Pro 版源码需付费订阅。

### 6. 使用方式简述
1. 从 `desk.hsslive.cn/#/download` 或 GitHub Releases 下载对应平台客户端（Windows / macOS / Android）。
2. 在被控端安装运行，获取设备码与连接密码（可自定义或开启开机自启）。
3. 在控制端客户端或浏览器打开 `desk.hsslive.cn` 输入设备码和密码连接。
4. 画质、帧率与码率在设置中调整；2K 或高帧率需购买 VIP（包月 6 元起）。
5. macOS 被控端需授予“屏幕录制”和“辅助功能”系统权限。

## 二、CrossDesk（`kunkundi/crossdesk`）

调研时约 6.5k Star、673 Fork，2023 年底建仓，几乎保持每周发版节奏，维护非常活跃。整体可靠性明显高于 BilldDesk，但距离完全替代 UU 远程仍有差距。

### 1. 核心架构与特性
- 基于作者自研的 **MiniRTC** 音视频库，支持 H264 / AV1 软硬编解码、Opus 音频与 SRTP 加密。
- **注意**：README 将其定位为 MiniRTC 的“实验性应用”，评估稳定性时需充分考虑这一点。
- **功能覆盖**：电脑 / 手机 / 浏览器 / 终端 CLI 四端互连、桌面墙群控、文件双向传输、隐私屏、无人值守、**局域网 IP 直连**（无需服务器，6 位密码）、可信设备认证、自托管。
- **MCP 能力（与 UU 远程最大差异点）**：内置 MCP 支持，允许 AI Agent 在授权下查看屏幕、操作键鼠、传输文件——这是 UU 远程原生不具备的能力，与本项目的 Agent 远程控制方向高度相关。
- **许可证**：README 标注为 LGPL-3.0，可商用。

### 2. 能否替代 UU 远程
- **追求开箱即用、低延迟游戏、少折腾**：暂时**无法替代**，UU 远程的商业优化与官方中继节点目前更稳。
- **重视隐私自托管、需要 MCP / CLI / 局域网 IP 直连、不想付费**：目前最接近 UU 的免费开源替代，功能面已经足够，但需接受一定折腾成本和稳定性波动。

### 3. 好用程度与已知问题
- **优点**：安装版配置简单（ID + 密码连接）；Web 客户端免安装；局域网 IP 直连不依赖外部服务器；迭代速度快、修复积极。
- **近期未关闭的核心问题（2026-11 调研快照）**：
  - 帧率锁在 30fps 左右（`#187`）
  - 鼠标定位不准（`#162`）
  - 自托管证书配置较繁琐
  - Windows 无人值守需使用 Release 版
- **自托管与公网 IP**：仅连官方服务器无需公网 IP；自托管需一台公网 IP 服务器（支持 Docker 一行命令部署）。

### 4. 结论与建议
- 技术向、偏重隐私自托管或 AI Agent 控电脑（MCP），值得纳入重点试用；纯图省心打游戏仍建议保留 UU 远程作主力、CrossDesk 作备用。
- 下一步验证建议：先在局域网使用 IP 直连实测延迟、画质与鼠标精准度，并核查 `#187` / `#162` 在最新版本中的修复状态。

## 三、横向对比摘要

| 维度 | UU 远程 | BilldDesk | CrossDesk | RustDesk |
| --- | --- | --- | --- | --- |
| 定位 | 商业低延迟 / 游戏向 | 个人开源 + 商业 Pro | 开源实验性全能远控 | 成熟开源远控 |
| 开源 / 协议 | 闭源商业 | 开源版不建议生产；Pro 闭源订阅 | LGPL-3.0（核心开源） | 开源成熟社区 |
| 自托管 | 不支持 | 支持（栈较重，开源版缺一键 Docker） | 支持（Docker 一行部署，证书略繁琐） | 支持（生态最成熟） |
| 特色能力 | 官方节点稳、低延迟 | 网页主控、群控、录屏 | **内置 MCP**、CLI、局域网 IP 直连 | 稳定、审计与社区成熟 |
| 当前主要短板 | 无原生 MCP、部分高级能力受限 | 开源版已知难修缺陷、稳定性一般 | 近期存在 30fps 限制与鼠标偏移 issue | 游戏极低延迟不如串流方案 |
